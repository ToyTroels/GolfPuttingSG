# Release smoke tests

Run these journeys against the packaged application, not only a debugger build. Record platform, OS version, device, package hash, and pass/fail evidence. Stable selectors for the critical controls live in `src/GolfSG/Views/UiAutomationIds.cs` so these cases can be moved into Appium without relying on translated text.

## Course practice rounds (beta)

1. Enable beta features in Settings and open **Banerunde på billede · Beta**. Confirm it opens a menu with **Spil bane** and **Opsæt ny bane**. Creating a course must ask for its name first; check blank/whitespace validation, cancel without creating a course, the 100-character limit, and a valid trimmed name. After **Fortsæt**, the picture must be the first content on screen, without the setup heading, beta paragraph or name field above it. Confirm the keyboard is closed and the first tap places a start point. The name must appear in the title and remain prefilled and editable near **Gem bane**; renaming must update the title and save correctly. With no saved courses, open Play and use the empty-state setup action; verify the same name-first flow. Save a named course, verify return navigation, reopen Play and start it without entering setup. Use **Rediger bane**, save changes and verify the course list refreshes; editing keeps the existing name without asking again, while reopening **Opsæt ny bane** must ask for a new name and show a fresh course. Repeated taps must open only one prompt, page or round. Disable beta and confirm the menu entry is hidden, while saved results remain readable in History.
2. On the supplied image, create approach, chip/bunker and putting tasks. Tap and drag both markers, zoom, save/reopen/edit/delete shots, and verify the positions and lies. Saved shots must remain numbered on the map. The lower form must have one **Gem slag og fortsæt** button. With valid input, including with the keyboard open, it must save the shot, dismiss the keyboard, clear the editor and selection, scroll to the picture and make the next tap place a new start even near an existing marker. Editing an existing shot must update it in place without duplicating it. Missing start, target or lie, invalid measured distances and active calibration must keep the draft and its points intact without adding a shot or scrolling. Saved shots and unsaved course changes must remain intact; repeated taps must not add duplicates, leave the page busy or start multiple scroll operations. Drag a saved endpoint and verify live distance; drag its line and verify both positions move together without changing distance, name, lie or order. Drag to every image edge, cancel a drag, and verify rollback. Tap a marker without moving it and confirm a measured override survives; moving one endpoint clears it, while moving the whole line preserves it. Save/reopen the course and confirm placement. Check vertical dragging versus page scrolling on Android and Windows, including the read-only play map.
3. Create a new course and confirm setup uses the supplied facility picture without any picture chooser or upload action. Verify the picture remains available offline. Calibrate using two measured points, and verify two independent known distances. Apply a measured-distance override and confirm it takes precedence. Check planned distances 10.4, 10.5 and 10.6 m display as 10, 11 and 11 m in setup, play and result Start labels, including after save/reopen. Preserve precise measurements, scoring and geometry; a sub-half-metre putting task must remain valid even when its whole-metre label shows 0 m. Cancel calibration and verify prior state. Reopen existing saved layouts and unfinished rounds and confirm their original picture references remain usable; check the result view remains readable if its picture is missing.
4. Start the round and confirm **Slagoversigt** opens with all tasks, their names, whole-metre distances, lies, categories and progress such as **0/5 slag spillet**. Select a later task first, confirm its map and input, and save attempts with green/off-green finishing lies, a holed result and penalties using **Gem og næste slag**. Saving opens the next attempt from the same position until its configured count is reached, then the next remaining position. Open **Slagoversigt** and verify partly played tasks remain selectable, while completed tasks show total SG and cannot be selected again. Choose remaining tasks in a different order and verify progress and SG always correspond to the chosen task. Rapidly repeat selection, Save and Next and Finish; confirm exactly one result per submitted attempt and one history record.
5. Enter an unfinished outcome, force-close, reopen the beta menu and resume. Verify layout, original scale, order, results and current input. Save and Close and repeat. Confirm the menu and course list show progress and offer resume/discard; new-round buttons stay disabled until the active round is finished or explicitly discarded. Edit the reusable course while a round is active; verify the round keeps its original snapshot. Check return navigation after saving the final result and retry after a storage error without hiding known courses or implying an empty library.
6. Undo the latest result and re-enter it. Cancel discard, then confirm discard and verify the course remains but the round no longer resumes. Test failed draft/history writes and retry the final archive after relaunch without duplicates.
7. Open the completed result from Start and History, filter by **Banetræning · Beta**, and verify normal-round statistics/insights exclude it. Export/import the round and verify detailed outcomes; image files and reusable course libraries are not part of this export.
8. Check course setup, menu, course list and play in both device light and dark modes: text, placeholders, unselected picker titles and selected values must remain readable on the light course palette. Verify clearly outlined fields, bold action labels, the primary **Gem slag og fortsæt** action, and readable disabled controls while a round is active or I hul is selected. Check large text and narrow screens: Start/Mål/Zoom must fit, and long shot metadata must wrap without clipping buttons. Verify touch targets and protected back navigation with unsaved course edits.

9. Place both course-shot points and verify a compact whole-metre distance summary below the picture. It must say **Estimeret afstand** for image estimates and **Målt afstand** for a measured override. Drag current and saved shots and confirm live updates, including override clearing for an endpoint move, preservation for a whole-shot move and restoration after canceling. Select different saved shots and check the displayed distance matches the selected shot. Successfully using **Gem slag og fortsæt**, deletion of the selected shot and entering calibration must clear the summary; leaving calibration restores the current shot's distance. Check zoom, large text, light/dark mode and taps/drags across the picture: the summary must remain legible below the image without covering course details, blocking map input or moving the points.

10. After saving at least one shot, accidentally place a new start or begin editing a saved shot, then press **Gem bane**. Confirm **Tilbage** preserves the draft and stays on setup; **Kassér slag og gem** saves the existing layout without the pending changes and returns. With no saved shots, saving the course must retain the draft and require **Gem slag og fortsæt** first. Active calibration must remain intact and ask to finish calibration. If returning to the picture fails after a shot is added or updated, show that the shot remains in setup; retrying must not add a duplicate.

11. During a chosen task, enter a partial result and open **Slagoversigt**. Continue the same task and verify the input survives. Select a different task: cancel the switch and verify the original draft remains; confirm the switch and verify only that draft clears. Save and Close or force-close, resume through the overview and verify the selected task and input remain correct. Undo must restore the last task actually played and its result input, including after playing tasks out of course order; canceling an undo with pending input must preserve that draft. After all tasks are played, **Gem rundens resultat** must be reachable in the fixed bottom bar without scrolling through the overview, including on a course with many tasks. Complete and export/import the round; each outcome and SG must match the actual task played, while the reusable course keeps its original order and geometry. Resume legacy course data and verify its original sequence remains valid after migration.

12. On course score entry, confirm **Gem og næste slag** stays visible outside the scroll area while scrolling and with the keyboard open, large text enabled, a small display, and Android gesture/system navigation. Invalid distance or missing lie must keep the current attempt and show an error beside the button. A failed save must retain the draft and not advance; retry saves exactly one result. Select a position with several attempts, play its configured shots, then enter the results one by one. Each successful save must reset outcome fields and advance **Slag N af M**. While that position has remaining attempts, keep the input form at the user's scroll position without returning to the picture. After its last attempt, dismiss the keyboard and scroll to the next position's picture or the completed overview. Selecting positions out of order must still advance to a position with remaining attempts. On a one-attempt course or the final remaining attempt, verify **Gem sidste slag** leads to the completed overview and the fixed **Gem rundens resultat** action. The save-next button must be absent while choosing tasks in the overview; selection or archive errors must remain visible.

13. Set **Antal slag** to 5 for one position and 2 for another. Check the default of 1, accepted limits 1 and 100, and rejection of blank, zero, negative, fractional, nonnumeric and greater-than-100 input without losing the draft. Editing and dragging a saved shot must preserve its attempt count; saving it must reset the next draft to 1. Reopen the course and verify counts. Record two attempts at the first position, switch to the second, then return and verify **Slag 3 af 5** and **2/5 slag spillet**. Save/resume with pending input and undo after switching partly played positions; both must retain the correct result association and count. Complete all seven attempts and verify seven outcomes in History and export/import, each with its own SG and correct position/attempt label. Editing the reusable course's count during the round must not change the active round. Existing courses and rounds must retain one attempt per position after migration. After more than ten attempts, verify the play page previews the latest ten while the completed result retains every attempt.

14. In **Slagoversigt**, select a position and change **Antal slag** using **−** and **+** directly above **Spil slag**. Verify the count, round total and **Slag 1 af N** update together. Counts must stay between 1 and 100 and the round total below or equal to 1000. Adjust a different, unplayed position after playing elsewhere; this must preserve the current draft and results. Save/close or restart and confirm the overrides survive. Record one result at a position, then return to the overview: both count buttons must be disabled there with an explanation, while unplayed positions remain adjustable. A storage failure must leave the count and draft intact; retry must apply one change. Finish the round and verify its result contains the adjusted counts. Reopen **Rediger bane** and start a later round: both must retain the saved course's default counts.

## First launch and navigation (core)

1. Install with no prior GolfSG data and launch offline.
2. Confirm Start, New Round, Putting Games, History, and Settings open once even after rapid repeated taps.
3. Confirm the empty-history state is understandable and the in-app privacy page opens.

## Round categories and guided entry

1. Start a nine-hole round with putting, approach, and around-the-green enabled.
2. Complete an approach-to-short-game handoff, a short-game-to-putting handoff, and a hole completed directly from each category.
3. Navigate backward, edit values, use undo, and confirm carried distances and summaries remain consistent.
4. Finish early, save, reopen the result, edit it, and verify there is exactly one history entry.
5. Open a hole from the overview, advance through several holes, then tap "Til oversigt". Confirm the round overview opens immediately. Repeat after using the previous-hole arrow, with rapid repeated taps, on the final hole, and with guided input disabled. Verify entered values are preserved.
6. Open hole 1, use the hole picker to jump to untouched hole 13, then open round settings. Confirm selecting nine holes is refused, hole 13 remains editable, and its subsequent input appears in the overview and survives resuming the round.

## Persistence and recovery

1. Force-close during an active round, relaunch, and resume it at the same state.
2. Abandon an active round and confirm it no longer resumes.
3. Save a round, regular game, and benchmark; confirm the default History view shows all three.
4. Filter and sort History, then return to the default all-items view.
5. Export data, delete or replace local data, import the export, and verify all entries.
6. Validate recovery from a corrupt active file and a valid backup.

## Putting-game recovery

1. Start a training game, tour round, randomized bell-curve benchmark, and ladder benchmark in turn. Record several results, adjust the current putt count, force-close, and relaunch. Resume from Start or Putting Games; verify the original distances/order, progress, current input, score, and benchmark metadata.
2. Use Save and Close, resume again, and verify the same state. Cancel a discard/replacement prompt and verify the saved game remains. Confirm discard and verify it no longer resumes.
3. Finish a resumed game; verify one history entry and no remaining resume action after relaunch. Repeat the final save and verify no duplicate history entry.
4. With storage unavailable, verify a save failure leaves the current putt and recorded results intact, offers retry, and does not report a successful save-and-close.

## Practice-result corrections

1. During training, tour, randomized bell-curve, and ladder sessions, submit several results, undo the latest, and confirm it becomes current with its recorded count. Resubmit and verify progress, distances/order, totals, and SG without duplicated results.
2. Open "Se og ret registrerede putts", edit an earlier count, and verify totals/SG update while the current putt input and shot order stay unchanged. Cancel an edit and verify nothing changes.
3. Relaunch after an undo or edit and resume; verify the corrected state. Finish the game, edit from the completion screen, and verify one history entry with the original date and benchmark metadata, with no new unfinished game.
4. Simulate storage failures during undo/edit and verify the earlier state remains visible and can be retried. Rapid repeated taps must not submit or correct multiple results unintentionally.

## Preferences and accessibility

1. Switch between meters and feet and verify entry, results, and history formatting while stored calculations remain consistent.
2. Exercise the primary journeys at the largest supported text size without clipped or unreachable controls.
3. With the platform screen reader enabled, verify control names, hints, state, focus order, and actionable elements.
4. Check contrast and focus visibility in every supported theme.
5. Check the overview, round settings, and hole picker on Android with gesture navigation and system navigation buttons. Confirm controls remain reachable above system bars and around display cutouts.

## Packaging and lifecycle

1. Confirm the package identifier, version, build number, icon, splash screen, and display name.
2. Install over the previous release and verify existing data remains available.
3. Confirm the app works without network access and does not request unrelated permissions.
4. Background, resume, rotate/resize where supported, and repeat the active-round save path.
5. Verify Android APK/AAB and Windows MSIX signing identities match the intended production identities.

Any crash, data loss, duplicate mutation, inaccessible critical action, debug signing identity, or unexplained scoring change blocks distribution.
